# Frontend Skill

## Instructions

1. **Pages**
   - Build pages using framework routing conventions
   - Keep pages thin and focused on composition
   - Handle loading, error, and empty states explicitly
   - Respect authentication and access boundaries

2. **Components**
   - Create reusable, composable UI components
   - Keep components small and single-purpose
   - Separate presentational and stateful logic
   - Avoid unnecessary re-renders

3. **Layout**
   - Define shared layouts for consistent structure
   - Ensure responsive behavior across screen sizes
   - Use semantic HTML for accessibility
   - Support navigation and content hierarchy clearly

4. **Styling**
   - Apply consistent styling patterns
   - Prefer utility-first or modular CSS approaches
   - Ensure readable typography and spacing
   - Design for mobile-first responsiveness

--------------------------------------------------
BEST PRACTICES
--------------------------------------------------

- Component-driven development
- Clear separation of concerns
- Mobile-first and responsive design
- Accessibility by default
- Predictable state and data flow

--------------------------------------------------
COMMON PITFALLS TO AVOID
--------------------------------------------------

- Large, monolithic components
- Hardcoded layout assumptions
- Ignoring loading and error states
- Inconsistent styling patterns
- Tight coupling to backend behavior

--------------------------------------------------
EXAMPLE WORKFLOW (CONCEPTUAL)
--------------------------------------------------

Design:
Layout → Components → Pages → Styling

Implementation:
Mock Data → UI States → API Integration

--------------------------------------------------
SUCCESS CRITERIA
--------------------------------------------------

- UI is responsive and accessible
- Components are reusable and easy to reason about
- Layouts are consistent and scalable
- Styling is clean and maintainable
- Frontend can evolve independently of backend
